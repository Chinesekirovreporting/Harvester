## 二、需要优化的模块

### 8. StageManager（功能过于简单）
**位置**: `framework/managers/StageManager.ts`

**问题**:
```typescript
export class StageManager extends Manager {
    public scene:Scene
    public screenWidth:number;
    public screenHeight:number;
    
    protected init():void {
        // 空实现
    }
}
```
- 只存储了屏幕宽高和场景，但没有监听屏幕尺寸变化
- 功能过于简单，可以直接使用 Cocos Creator 的 `screen` API

**建议**:
- **选项1**: 如果不需要额外功能，删除 `StageManager`，直接使用 `screen.windowSize`
- **选项2**: 如果需要封装，应该实现屏幕尺寸变化的监听和事件分发

---

### 9. LoadManager（功能不完整）
**位置**: `framework/managers/load/LoadManager.ts`

**问题**:
- 大部分代码被注释
- 功能与 `AssetManager` 重复
- 只实现了测试方法，没有完整的资源加载逻辑

**建议**:
- **选项1**: 如果 `AssetManager` 已经满足需求，删除 `LoadManager`
- **选项2**: 明确 `LoadManager` 和 `AssetManager` 的职责划分
  - `LoadManager`: 负责资源加载（网络/本地）
  - `AssetManager`: 负责资源缓存和生命周期管理

---

### 10. EventManager vs Manager的EventTarget（功能重复）
**位置**: `framework/managers/EventManager.ts`

**问题**:
- `Manager` 基类已经继承了 `EventTarget`（Cocos Creator提供）
- `EventManager` 重新实现了事件系统，功能重复
- 但 `EventManager` 提供了全局事件管理，这是额外价值

**建议**: 
- **保留** `EventManager`，但考虑是否可以直接使用 `EventTarget`
- 如果保留，应该注释说明为什么需要自定义实现（比如需要全局事件总线）
