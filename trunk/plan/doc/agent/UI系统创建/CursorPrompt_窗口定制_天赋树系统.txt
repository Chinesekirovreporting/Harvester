你是一名 UI 程序设计师，负责 FairyGUI 的 UI 制作和 TypeScript 脚本编写。请参考魔兽世界天赋系统的核心设计，基于现有表格、代码和 FGUI 项目目录，完成天赋树系统的开发。

## 一、魔兽世界天赋系统参考要点

### 1.1 核心结构
- **层级结构**：天赋分为多层（如 6 层），每层有若干可选天赋
- **单层单选**：同一层内通常只能选择其中一项（抉择节点）
- **前置依赖**：某些天赋需要先点亮前置天赋才能解锁
- **天赋点**：玩家通过等级/任务获得天赋点，用于点亮天赋
- **多分支**：可支持多个天赋树（如职业专精），每个树独立加点

### 1.2 节点类型（可选实现）
- **普通节点**：消耗 1 点，直接点亮
- **抉择节点**：同一层二选一或三选一
- **基石/顶石**：特殊节点，作为树的起点或终点

### 1.3 本项目的简化约定
- 天赋树为**有向图**：节点有唯一 ID，通过 PreReqIds 指定前置
- 每层可设 Layer 字段，同层为抉择关系（互斥）或可多选（由配置决定）
- 天赋点来源：等级解锁（如每 N 级 1 点）或任务奖励，具体由策划表配置

## 三、表格数据结构（需新建）

### 3.1 天赋表（TalentCFG）

**路径**: `tableClass/$TalentCFG.ts` / `TalentCFG.ts`

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | number | 天赋ID |
| TreeId | number | 所属天赋树ID（支持多树） |
| Name | string | 天赋名称 |
| Desc | string | 天赋描述 |
| Icon | string | 图标资源名 |
| Layer | number | 层级（1-N，同层可设互斥） |
| PreReqIds | number[] | 前置天赋ID列表，空则无前置 |
| MaxRank | number | 最大等级（1=单点，>1=可多点强化） |
| EffectIds | number[] | 效果ID列表（可选，关联技能/属性） |

### 3.2 天赋树表（TalentTreeCFG，可选）

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | number | 天赋树ID |
| Name | string | 树名称（如「专精A」） |
| UnlockLevel | number | 解锁等级 |
| MaxPoints | number | 该树最大可分配点数（0=不限制） |

### 3.3 导表与配置
- Excel 存放于 `trunk/plan/excel/`
- 在 `excel_to_ts_config.json` 的 `table_name_map` 中注册新表
- 若暂不建表，可先用硬编码测试数据验证逻辑

## 四、存储结构

### 4.1 StorageKeys
在 `StorageKeys.ts` 中新增：
```typescript
/** 天赋加点 { treeId: { talentId: rank } } */
TALENT_POINTS: "harvester_talent_points",
```

### 4.2 存储格式
- 类型：`Record<number, Record<number, number>>`
- 外层 key：天赋树 ID
- 内层 key：天赋 ID
- 内层 value：已点等级（rank，1~MaxRank）

示例：`{ 1: { 101: 1, 102: 2, 103: 1 } }` 表示树1中，天赋101点1级，102点2级，103点1级

## 五、开发规范（必须遵循）

### 5.1 数据模型（ModelTalent）
- 继承 `AbstractModel`
- 使用 `App.cookieManager.get/set` 读写 `StorageKeys.TALENT_POINTS`
- 提供方法：
  - `getTalentList(treeId?: number): TalentCFG[]` - 获取天赋列表，可按树筛选
  - `getTalentRank(treeId: number, talentId: number): number` - 获取某天赋已点等级
  - `getSpentPoints(treeId: number): number` - 某树已消耗点数
  - `canLearn(treeId: number, talentId: number): boolean` - 是否可学习（前置+点数检查）
  - `learnTalent(treeId: number, talentId: number): boolean` - 学习天赋，返回是否成功
  - `resetTree(treeId: number): void` - 重置某树（归还点数）
- 在 `GameModels.init()` 中初始化并挂载到 `GameModels.talent`

### 5.2 窗口类（WindowTalent）
- 继承 `AbstractUIWindow`
- 实现 `getResList()` 返回 `["ui/Talent", "ui/Icon"]`
- 在 `onInit()` 中：
  - `UICore.registerExtension("Talent", "RenderTalentNode", RenderTalentNode)`
  - `UICore.createObject("Talent", "WindowTalent").asCom` 创建视图
- 在 `onInitView()` 中获取：
  - `graphTalent`(GGraph) 或 `containerNodes`(GComponent) - 天赋节点容器
  - `lblPoints`(GTextField) - 剩余天赋点显示
  - `btnReset`(GButton) - 重置按钮
  - `btnClose`(GButton)、`btnClose`(GButton)
- 天赋树布局：根据 TalentCFG 的 Layer、PreReqIds 计算节点坐标，或用配置的 X、Y 字段
- 在 `onShow()` 中：刷新天赋树显示、更新点数
- 在 `onDispose()` 中解绑事件、置空引用

### 5.3 天赋节点渲染器（RenderTalentNode）
- 继承 `GButton` 或 `GComponent`
- 重写 `onConstruct()` 获取：loaderIcon、lblName、lblRank、imgLocked 等
- 实现 `setData(talentCFG: TalentCFG, rank: number, canLearn: boolean)`：
  - 已点亮：显示图标、名称、等级，可点击查看
  - 未点亮可学：高亮边框，点击学习
  - 未点亮不可学：灰显/锁定，点击提示「需要前置」或「天赋点不足」
- 支持 MaxRank>1 时显示当前等级（如 2/3）

### 5.4 天赋树连线（可选）
- 若有 GGraph，可用 `drawRect`/`drawLine` 或预制连线图，根据 PreReqIds 绘制节点间连线
- 或使用 FGUI 的 GImage 作为连线，根据节点位置动态设置

### 5.5 窗口注册
- 在 `ModuleWindow.init()` 的 `_windowClassDict` 中注册：`"WindowTalent" = WindowTalent`
- 添加 import

## 六、FGUI 设计要点

### 6.1 WindowTalent 布局
- 参考魔兽天赋界面：中央为天赋树画布，可滚动查看
- 顶部：标题「天赋」、剩余点数 lblPoints、重置按钮 btnReset

- 状态：正常、可学习（高亮）、锁定（灰+锁图标）
- 子组件命名与 `getChild()` 一致

### 6.3 节点坐标
- 方案 A：在 TalentCFG 中增加 X、Y 字段，直接配置坐标
- 方案 B：根据 Layer、同层索引自动计算（如 Layer 决定 Y，索引决定 X）

## 七、交互逻辑

### 7.1 学习天赋
1. 点击未点亮且可学的节点 → 调用 `ModelTalent.learnTalent()` → 刷新界面
2. 检查：前置是否满足、剩余点数是否足够、同层是否互斥（若配置了互斥）

### 7.2 重置
- 点击 btnReset → 确认弹窗 → `ModelTalent.resetTree(treeId)` → 刷新

### 7.3 天赋点来源（与 ModelRole 联动）
- 当前可用点数 = 总获得点数 - 已消耗点数
- 总获得点数：可从 `ModelRole` 的等级计算，如 `Math.floor(level / 5)`，或从单独配置表读取
