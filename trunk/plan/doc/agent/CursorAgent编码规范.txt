# Cursor Agent 编码规范（项目约定）

本文档供人类与 Agent 共同遵守；生成或修改代码时，应优先对齐本仓库既有风格与目录结构。

---

## 一、值对象（Vo）文件组织

### 1.1 一类型一文件

- 每个 **Vo 类型** 使用 **独立** 的 `*.ts` 文件，文件名与类型名一致：`{Name}Vo.ts` 内导出 `class {Name}Vo`（或与项目内既有 `BuffVo`、`SkillVo` 等命名一致）。
- **禁止** 在较大的聚合 Vo（如 `BattleVo`）中内联声明其它业务用的 interface / 独立数据结构；若某结构会被多处引用或单独演进，应抽成独立 `{Xxx}Vo.ts`。
- 与表格行类型（如 `ItemCFG`）区分：`ItemCFG` 属于导表生成的配置行类型；运行时 **数据体 / 值对象**（背包、英雄、战斗结算掉落等，如 `ItemVo`、`HeroVo`、`BattleRewardDropItemVo`）统一放在 `game/gameModel/data/`，由业务模块按需 import。
- `core_fight` 等目录下的 `*Vo`（如 `BuffVo`、`SkillVo`）表示战斗核心子系统内对象，**不要** 把与 `ItemCFG` 对齐的背包/结算类 DTO 塞进 `core_fight`，应归入 `gameModel/data`。

### 1.2 Vo 类写法

- 使用 **class** 声明（与 `BuffVo`、`SkillVo` 一致），公开字段 + 必要时的 **constructor** 初始化。
- 字段语义、与配置表的对应关系用 **简短文件头注释** 或字段旁一行注释说明即可，避免冗长模板注释。

### 1.3 引用与导入

- 业务代码从 **定义 Vo 的文件** 直接 import，例如：`import { BattleRewardDropItemVo } from ".../gameModel/data/BattleRewardDropItemVo"`；**不要** 从 `BattleVo.ts` 再导出子类型以「顺带」提供类型（避免隐式耦合）。

---

## 二、Prompt 生成规范（让 Agent 产出符合上述约定的代码）

在编写或维护 **Cursor Prompt**（如 `CursorPrompt_窗口定制_*.txt`）时，对「新增数据结构」类需求应写明：

1. **文件**：`game/gameModel/data/{Name}Vo.ts`（运行时数据体统一目录），单文件单类型；若确属战斗核心框架内部类型再放在 `core_fight` 对应子目录。
2. **类型**：`export class {Name}Vo { ... }`，字段与构造函数与现有 `BuffVo` / `SkillVo` 风格一致。
3. **聚合关系**：若仅作为 `BattleVo` 等字段的元素类型，在 Prompt 中写清「`BattleVo` 中字段类型为 `{Name}Vo[]`，并在 `BattleVo.ts` 中 `import` 该 Vo 文件」，**不要** 要求在 `BattleVo.ts` 内嵌 interface。
4. **使用方**：列出需改 import 的窗口/战斗模块（如 `RenderXxx`、`WindowFightCore`），避免仍从旧路径引用类型。

将以上四条复制进具体任务的「开发规范」小节，可减少 Agent 把辅助类型塞进大 Vo 文件的情况。

---

## 三、Cocos / 资源

- 新增 `*.ts` 后若引擎需要，应存在对应的 `*.ts.meta`（uuid 唯一）；以编辑器自动生成为准，Agent 新增脚本时按同目录已有 `.meta` 格式补全并确保 uuid 不重复。
