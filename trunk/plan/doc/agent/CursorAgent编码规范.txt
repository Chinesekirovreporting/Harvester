# Cursor Agent 编码规范（项目约定）
本文档供人类与 Agent 共同遵守；生成或修改代码时，应优先对齐本仓库既有风格与目录结构。
## 一、值对象（Vo）文件组织
### 1.1 一类型一文件
- 每个 **Vo 类型** 使用 **独立** 的 `*.ts` 文件，文件名与类型名一致：`{Name}Vo.ts` 内导出 `class {Name}Vo`（或与项目内既有 Vo后缀的 命名一致）。
- **禁止** 在较大的聚合 Vo（中内联声明其它业务用的 interface / 独立数据结构；若某结构会被多处引用或单独演进，应抽成独立 `{Xxx}Vo.ts`。
- 与表格行类型（如 `ItemCFG`）区分：`ItemCFG` 属于导表生成的配置行类型；运行时 **数据体 / 值对象**（背包、英雄、战斗结算掉落等，如 `ItemVo`、`HeroVo`、`BattleRewardDropItemVo`）统一放在 `game/gameModel/data/`，由业务模块按需 import。
- 非战斗核心子系统内对象，应归入 `gameModel/data`。

### 1.2 Vo 类写法
- 使用 **class** 声明，公开字段 + 必要时的 **constructor** 初始化。
- 字段语义、与配置表的对应关系用 **简短文件头注释** 或字段旁一行注释说明即可，避免冗长模板注释。

### 1.3 AI编码时，自动引用与导入
- 业务代码从 **定义 Vo 的文件** 直接 import，例如：`import { BattleRewardDropItemVo } from ".../gameModel/data/BattleRewardDropItemVo"`

## 二、Prompt 生成规范（让 Agent 产出符合上述约定的代码）
在编写或维护 **Cursor Prompt**（如 `CursorPrompt_窗口定制_*.txt`）时，对「新增数据结构」类需求应写明：
1. **文件**：`game/gameModel/data/{Name}Vo.ts`（运行时数据体统一目录），单文件单类型；若确属战斗核心框架内部类型再放在 `core_fight` 对应子目录。
2. **类型**：`export class {Name}Vo { ... }`，字段与构造函数与现有 Vo文件 风格一致。

## 三、类成员可见性（public / private / protected）
- **对外 API**：供其它模块、窗口、业务代码调用的 **方法、getter 等** 使用 `public`。
- **内部实现**：仅本类内部使用的 **字段、辅助方法** 使用 `private`。
- **继承与框架钩子**：与基类约定一致的生命周期或模板方法（如 `AbstractModule` 的 `init`、`show`、`remove`）须与基类保持相同可见性，一般为 **`protected`**（不可为 `private`，否则无法重写）；除非设计明确要求对外直接调用，否则不必改为 `public`。

## 四、索引与容器（Map ）
- 若团队希望行为直观、生命周期由代码显式管理，优先使用 **`Map<K, V>`**（或普通对象）存放「宿主 → 子对象」等映射；在模块 `remove`、资源 `dispose`、`releaseXxx` 等路径中 **`clear()` 或 `delete`**。
- **`WeakMap`** 适合「键为对象且随键 GC 自动回收条目」的场景，但可读性与调试成本较高；不使用时须在文档或注释中说明：**调用方在宿主销毁前调用模块提供的释放接口**，避免 `Map` 键引用导致无法回收。非必要不使用WeakMap。
